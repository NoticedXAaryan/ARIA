Desktop Phone Background — who does what
1
Install desktop app Desktop
User downloads one installer (.exe / .dmg / AppImage). It installs the Python daemon + a small system tray icon. Nothing else to configure.
On first launch → OAuth popup: "Connect Google Calendar?" → done in 30 seconds.
Points to local notes folder (Obsidian vault, or any folder with .md files).
Installs ActivityWatch silently in the background if not already present.
No account. No cloud signup. Everything local.
2
Phone app (companion, not required) Phone
Phone app is optional but recommended. It adds two things desktop alone can't do: location context and away-from-desk nudges.
Connects to the desktop daemon over local WiFi (same network) — no cloud relay needed.
Sends: location coarse signal (home/office/commuting), phone calendar events, any tasks added on mobile.
Receives: nudges forwarded from desktop when user is away from desk.
If no phone → desktop-only mode works fine. Just no mobile nudges.
3
Runs silently for 1–2 weeks Background
This is the cold start period. ARIA is watching but barely surfacing anything. It needs your patterns before it can predict them.
Daemon runs a 15-min check loop. Reads calendar, notes folder, ActivityWatch logs.
Builds the episodic memory store (what happened, when).
Starts fitting the temporal rhythm model from day 5 onward.
User sees almost nothing during this phase — that's intentional and should be communicated on install.
4
System tray popup — primary surface Desktop
After cold start, nudges begin appearing as a small floating card anchored to the system tray icon. This is the main interaction point.
Card appears bottom-right (or wherever OS puts tray notifications).
Shows: what + why + one-tap actions (Start / Snooze 30m / Dismiss).
Auto-dismisses after 12 seconds if ignored — logs "ignored" as feedback signal.
Card does NOT interrupt if: fullscreen app is open, microphone is active (you're in a call), or last nudge was <45 min ago.
Clicking the tray icon at any time opens the dashboard.
5
Dashboard — on demand only Desktop
User opens dashboard by clicking tray icon. It's a local browser page (localhost:7860). Not meant to be checked constantly — more like a weekly review surface.
Today view: what nudges fired, what was accepted/dismissed, current focus state.
Patterns tab: visual of the learned rhythm (the GNN graph from earlier).
Settings: focus hours, nudge intensity, which data sources are connected, memory scope.
Feedback tab: correct ARIA where it was wrong ("this was not urgent").
No mobile dashboard — keep it simple. Phone is just for nudge delivery when away from desk.
6
Gets smarter over time Background
Every accept/snooze/dismiss feeds back into urgency weights. Every week the GNN retrains on accumulated data. After 4–6 weeks it's calibrated to this specific user.
Nightly job (2am): re-trains rhythm model on last 30 days of activity logs.
Weekly: re-summarizes semantic memory (compresses old episodic events into facts).
User never sees or triggers this — it just gets quieter and more accurate over time.
